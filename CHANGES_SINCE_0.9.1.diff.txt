+# Strop 1.0 Release Roadmap
+
+This roadmap defines the work needed to make Strop 1.0 reliable to install, use, and support. The 1.0 goal is a stable end-to-end workflow for supported hardware, with clear limits and verified behavior.
+
+## Release principles
+
+- A user can discover a supported device, edit a profile, save it, apply it, and confirm its state.
+- Strop reports failures and uncertain outcomes accurately.
+- The documented hardware and platform support matches what has been tested.
+- Existing profiles and user macro data survive upgrades and can be recovered.
+
+## Priority 1: Stabilize profile lifecycle
+
+- [ ] Confirm save, apply, stop, and active-profile status match the input-remapper backend result.
+- [x] Validate preset data before saving or applying it.
+- [x] Write profile and state files atomically to avoid corruption from interrupted writes.
+- [x] Preserve the last confirmed state when apply or stop fails; show uncertain state after timeouts.
+- [x] Handle missing input-remapper, daemon failures, permission problems, device disconnects, and stale state with actionable messages.
+- [x] Verify imported presets round-trip through Strop without losing mappings, labels, or target information for mappings Strop can edit; preserve other valid mappings on save.
+
+## Priority 2: Define supported hardware and platforms
+
+- [x] Publish the sole 1.0 hardware target matrix and distinguish device detection from end-to-end verification.
+- [x] Mark catalog-only devices separately from devices verified end to end.
+- [x] List the supported Linux distribution, desktop session, and input-remapper/OpenRazer versions.
+- [x] Document required packages, device permissions, service setup, and known X11/Wayland limitations.
+- [x] Make device discovery explain permission and driver errors instead of presenting them as an empty device list.
+

+# Backup, upgrade, and recovery
+
+This guide covers Strop 0.9.1 to later 0.9.x/1.0 packages. It has not yet been exercised as a clean-system upgrade; verify it on the Steam PC before declaring upgrade support.
+
+## Back up profiles and settings
+
+Strop keeps its macro library and last-confirmed profile labels in `~/.config/strop/`. Input-remapper stores the actual user presets in `~/.config/input-remapper-2/presets/` on current installations; older installations may use `~/.config/input-remapper/presets/`.
+
+Close Strop editors, then copy any existing data directories into a timestamped backup:
+
+```bash
+backup="$HOME/strop-backup-$(date +%Y%m%d-%H%M%S)"
+mkdir -p "$backup"
+for path in .config/strop .config/input-remapper-2/presets .config/input-remapper/presets; do
+    if [ -e "$HOME/$path" ]; then
+        mkdir -p "$backup/$(dirname "$path")"
+        cp -a "$HOME/$path" "$backup/$path"
+    fi
+done
+tar -C "$backup" -czf "$backup.tar.gz" .
+echo "Backup saved to $backup.tar.gz"
+```
+
+Keep the archive somewhere outside the PC if it is your recovery copy. Strop's `active_profiles.json` records the last profile Strop confirmed; it does not represent the live injection state. The input-remapper preset files are the important mapping data.
+
+## Upgrade
+
+1. Use Strop/input-remapper to stop active profiles before upgrading, then close Strop windows.
+2. Install the downloaded package with `sudo apt install ./strop_VERSION_all.deb`.
+3. Launch Strop and input-remapper, confirm the devices and saved presets appear, and apply a profile only after reviewing its mappings.
+
+Package installation does not intentionally remove user configuration. Do not run the Strop application with `sudo`.
+
+## Restore
+
+Close Strop and input-remapper, then extract the backup into the same user's home directory:
+
+```bash
+tar -C "$HOME" -xzf "$HOME/strop-backup-YYYYMMDD-HHMMSS.tar.gz"
+```
+
+This overlays the saved directories. It does not delete newer files that were added after the backup. For an exact rollback, first move the current Strop directory and whichever input-remapper preset directory you use aside, then extract the archive. Restore files as your desktop user; avoid `sudo` so ownership remains correct.

+# Strop first-run and profile guide
+
+Use this guide with the supported PC and devices listed in [SUPPORT.md](SUPPORT.md). Device discovery alone does not mean a mapping has been verified.
+
+## Before launching
+
+- Install Strop and the documented runtime dependencies.
+- Ensure input-remapper 2.2.0 is installed and its service is running. Check with `systemctl status input-remapper` and `input-remapper-control --command hello`.
+- Launch Strop as your logged-in desktop user. Do not use `sudo` for the application.
+
+## Create and apply a profile
+
+1. Launch Strop from the application menu or run `strop` after installing the package. In a source checkout, run `./strop.py` from the project directory.
+2. Confirm the intended device appears in the hub. Use **Rescan** if needed. Review any discovery diagnostic before opening a studio.
+3. Open that device's studio, select an input on the layout, and edit its output and target. Only supported single gamepad-button outputs are available for gamepad mapping; digital-to-analog stick and trigger bindings are not supported by the 1.0 backend.
+4. Enter a preset name. In the Presets section, use **Save** to write the preset, or **Apply** to save it and request input-remapper to start it.
+5. Confirm the result in Strop's status message. An unknown/timeout result means Strop cannot confirm whether the backend changed state; inspect input-remapper before retrying.
+6. Use **Stop** to ask the backend to stop injection for the selected device. Confirm the reported result.
+
+The hub also offers **Apply Settings** and **Stop** for the selected device/profile. A label such as “Last Strop profile” is Strop's last confirmed operation, not live proof that the profile remains active if another tool changes injection state.
+
+## Import and export presets
+
+- Use **Load** to import an input-remapper JSON preset. Strop reports how many mappings it can edit. Valid mappings outside Strop's editor model are preserved when the preset is saved.
+- Use **Save** to write the current editor state to the selected device's input-remapper preset directory.
+- Keep a separate backup before replacing a profile. See [UPGRADING.md](UPGRADING.md) for backup and restore instructions.
+
+## Macros
+
+Macro Studio saves custom macros under `~/.config/strop/macros.json`. Built-in templates are read-only. Macro syntax must be accepted by the installed input-remapper parser when that parser is available.
+
+## Common problems
