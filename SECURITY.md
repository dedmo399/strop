# Security reporting

## Version scope

The current release is Strop 1.1.0. Report suspected vulnerabilities against the
latest release or `main`, and include the affected version. Older releases do not
have a separate security maintenance commitment. There is no guaranteed response
or fix timeline.

## Report a suspected vulnerability

Do not publish exploit details, credentials, personal information, or sensitive
logs in a public issue or pull request.

Check the repository's [Security page](https://github.com/dedmo399/strop/security).
If **Report a vulnerability** is available, use that private reporting channel.
If it is unavailable, open an issue containing only a request for a private
security contact, without vulnerability details, and wait for the maintainer to
arrange a private channel. No public security email address is currently listed.

Once a private channel is established, include the affected version, environment,
reproduction steps, impact, and any proposed mitigation. Share only the minimum
data needed to reproduce the issue, with personal information removed.
